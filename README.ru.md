# diafan-blog-autoposter

**Автопостинг статей в блог на Diafan.CMS: от темы в очереди до опубликованной
страницы одной командой.** Конвейер — генерация текста, блокирующая проверка,
перелинковка, обложка, публикация и переобход в Яндексе — работает на вашей
машине и отправляет на сайт **ровно один HTTP-запрос на статью**.

Diafan.CMS — CMS без API публикации, с базой, которая принимает соединения
только с localhost, и хостингом, который блокирует IP после нескольких частых
запросов. Отсюда архитектура: вместо автоматизации админки или записи в MySQL
снаружи на сайте живёт небольшой PHP-endpoint, закрытый токеном, и сохраняет
статью тем же путём, что и админка — вместе с кэшем, нарезкой картинок и
индексами.

## Что решает

| Проблема | Решение |
| --- | --- |
| В Diafan.CMS нет API публикации | `server/publisher.php` поднимает ядро CMS и сохраняет запись «изнутри» |
| База закрыта для внешних подключений | Вся запись идёт на стороне сайта, внутри endpoint'а |
| Хостинг блокирует IP после 3–5 частых запросов | Один POST на статью, пауза и экспоненциальный бэкофф на клиенте, 90 с между статьями |
| FTP даёт ~1 подключение в 30–60 с | Деплой и бэкапы — одно соединение на запуск, вместо сломанного `LIST` используется `MLSD` |
| Сгенерированный текст не совпадает с вёрсткой сайта | `verify.py` блокирует публикацию при любом отклонении от контракта HTML |
| Модель выдумывает цифры | Писателю отдаётся только `data/facts.json`, выдумывание запрещено промптом |
| Бесконечные перегенерации | Модель исправляет **только** перечисленные замечания поверх своей прошлой версии |

Показатели боевой работы: две статьи в день, **1–2 минуты на статью**, около
пяти минут на две вместе с технической паузой, один запрос к сайту на статью.

## Возможности

- ⚙️ **Один запрос на статью** — POST публикует запись, строит ЧПУ, загружает и
  нарезает обложку, сбрасывает кэш.
- 🔒 **Точка записи под токеном** — заголовок `X-Publisher-Token`, только POST,
  `noindex`, идемпотентность по `external_id`, режим `inspect` для диагностики.
- ✅ **Блокирующий валидатор** — контракт вёрстки (теги, классы, лид, таблица,
  список, CTA, FAQ) плюс чек-лист AI SEO (числа в каждом разделе, запрет хеджей
  и рекламных штампов, объём).
- 🔗 **Детерминированная перелинковка** — модель лишь употребляет анкорные
  формулировки, линкер находит их по основам слов и ставит 3–4 ссылки, по одной
  в разные `<h2>`, не в лид, не в таблицу и не в FAQ.
- 🖼️ **Обложки 800×510** — подбор из Pexels с откатом на заглушку Pillow, либо
  свои картинки пачкой по слагам.
- ♻️ **Устойчивая очередь** — тема уходит из `data/themes.txt` только после
  успешной публикации.
- 🔁 **Точечные правки вместо перегенерации** — при замечаниях модель получает
  свою прошлую версию и список замечаний.
- 🔎 **Переобход в Яндексе** — адрес уходит сразу после публикации; кэш
  идентификаторов даёт один запрос вместо трёх, сбой переобхода не отменяет
  публикацию.
- 🧪 **31 тест конвейера** — без сайта, сети и ключей.

## Как это работает

```
тема из очереди
      │
      ├─ writer.py     LLM пишет статью по prompts/writer.md
      │                (строгий JSON; ссылок не ставит)
      ├─ verify.py     проверка ЧЕРНОВИКА: контракт вёрстки + чек-лист AI SEO
      ├─ linker.py     детерминированно вплетает 3–4 ссылки, по одной в разные <h2>
      ├─ verify.py     проверка ФИНАЛА
      ├─ images.py     обложка 800×510 (сток или своя через set_cover.py)
      └─ diafan.py     один POST на сайт → publisher.php
                       (INSERT news + ЧПУ + загрузка картинки + сброс кэша)
                          │
                          └─ recrawl.py → Яндекс.Вебмастер: переобход нового адреса
```

## Требования

- Сайт на **Diafan.CMS 7.0** с доступом по FTP (endpoint кладётся в корень сайта
  и берёт реквизиты БД из собственного `config.php` сайта).
- Python 3.10+ с `requests` и `Pillow`.
- PowerShell 7 или Windows PowerShell 5.1 — либо запуск Python-скриптов напрямую,
  сам конвейер кроссплатформенный.
- Ключ DeepSeek API либо локальная модель с OpenAI-совместимым endpoint (Ollama).
- Опционально: ключ Pexels для автоподбора обложек и OAuth-токен
  Яндекс.Вебмастера для переобхода.

## Быстрый старт

```bash
git clone https://github.com/YanChi-pixel/diafan-blog-autoposter.git
cd diafan-blog-autoposter
python -m venv .venv && . .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

1. **Секреты.** Скопируйте `.env.example` в `.env` и заполните `SITE_URL`, доступ
   по FTP, `DEEPSEEK_API_KEY` и свежий `PUBLISHER_TOKEN`:

   ```bash
   python -c "import secrets; print(secrets.token_hex(24))"
   ```

2. **Настройте `config.json`** под свой сайт: `site.base_url`,
   `site.news_site_id` (id страницы, к которой привязан модуль новостей) и, если
   нужен предпросмотр со стилями сайта, `site.preview_css`.

3. **Задеплойте endpoint и осмотритесь** (одно FTP-соединение на команду):

   ```bash
   python src/deploy.py publisher     # заливает publisher.php, подставляя токен из .env
   python src/deploy.py ls            # что лежит в корне сайта
   python src/diafan.py               # GET ?action=inspect → output/inspect.json
   ```

   `inspect` показывает схему таблицы новостей, вариации картинок, образцы ЧПУ,
   версию CMS и права на запись.

4. **Соберите каталог сайта** (whitelist ссылок и существующие статьи для
   антидубля):

   ```bash
   python src/catalog.py
   ```

5. **Адаптируйте промпт писателя.** `prompts/writer.md` — пример под B2B-услуги
   для промышленных предприятий: замените блок `РОЛЬ` на свою компанию и
   отрасль. Контракт HTML, структура и чек-лист ниже универсальны.

6. **Подготовьте данные** (см. `examples/README.md`):

   ```bash
   cp examples/themes.example.txt data/themes.txt     # очередь тем
   cp examples/facts.example.json data/facts.json     # только проверенные цифры
   ```

7. **Прогон без записи, затем публикация.**

   ```bash
   python src/run_one.py --no-publish      # только генерация, проверка и превью
   python src/run_one.py --dry-run         # плюс проверка endpoint'а без записи
   python src/run_one.py                   # опубликовать первую тему из очереди
   ```

   В Windows то же одной командой: `.\publish.ps1 -Count 2` — две статьи с паузой
   90 секунд между ними.

## Команды

```powershell
.\publish.ps1 -Count 2        # две статьи подряд (паузу держит сам скрипт)
.\preview.ps1                 # сгенерировать и открыть предпросмотр, сайт не трогает
.\schedule.ps1                # необязательно: задача дважды в день

```

```bash

python src/check.py                         # догнать отложенные пост-проверки
python src/set_cover.py --list              # какие статьи ждут свою картинку

python src/recrawl.py --queue               # очередь и остаток квоты Вебмастера

python tests/test_pipeline.py               # 31 проверка конвейера
```

## Грабли, пройденные на практике

Полный разбор — в `ARCHITECTURE.md`, §11. Коротко:

1. **Целое число в ENUM-колонке MySQL — это индекс, а не значение.** Первая
   боевая публикация молча ушла в черновики и отдавала 404, потому что `act = 1`
   MySQL прочитал как «первый член перечисления». Публикатор теперь запрашивает
   типы колонок через `SHOW COLUMNS` и всегда квотирует enum-значения строками.
2. **`DB::query()` в Diafan при ошибке возвращает `false` и молчит.** INSERT и
   UPDATE идут напрямую в `DB::$backend->query()` внутри `try/catch`, чтобы был
   виден текст ошибки SQL.
3. **Битый `element_id` во внутреннем формате ссылок Diafan молча превращается
   в ссылку на главную.** Поэтому линкер ставит обычные абсолютные URL: их можно
   проверить, и они не деградируют тихо.
4. **CTA-блок не нужно верстать** — одного тега
   `<insert name="show_form" module="feedback" template="ask" site_id="…">`
   достаточно, Diafan разворачивает его в готовую форму со скрытыми полями.
5. **Обе вариации картинки совпадают.** Diafan режет `smalla` до 800×800,
   `large` — до 1200×1200, но не увеличивает изображение, поэтому источник
   800×510 даёт одинаковый файл в обеих папках.
6. **Правки шаблонов — только через `custom/`.** Diafan ищет шаблон сначала в
   `custom/<модуль>/views/`, поэтому переопределение не сотрётся при обновлении CMS.
7. **Полная перегенерация осциллирует, точечные правки сходятся.** Замер: попытка
   1 — 2116 слов и «нет чисел в разделе»; попытка 2 — 1348 слов и уже ошибка
   объёма; попытка 3 — лишний заголовок «Заключение». С точечными правками та же
   статья прошла за две попытки: 2284 слова.
8. **Мягкому поиску анкоров нужен стоп-лист.** После разбиения по дефису
   «аренда ит-персонала» распадалась на «аренда» + «персонала», и линкер привязал
   обычную фразу к странице ИТ-услуг. Теперь дефис — часть слова, а анкоры из
   одних родовых слов мягко не ищутся.
9. **Планировщик Windows молча роняет задачу двумя способами.** Без BOM
   `Windows PowerShell 5.1` читает `.ps1` как ANSI и падает на русских строках —
   поэтому все `.ps1` сохранены с BOM. А чтение stdout и stderr дочернего
   процесса через `ReadToEnd()` даёт дедлок: лог пишет сам Python (`--log`),
   PowerShell читает только код возврата.
10. **Правка файла темы без бэкапа уронила сайт в HTTP 500:** в теме `$this` —
    это `Parser_theme`, а не контроллер модуля, поэтому `$this->htmleditor()`
    даёт fatal error. Перед любой правкой — `deploy.py backup`.
11. **PHP в теме исполняется до разбора `<insert>`**, поэтому обернуть вставку в
    `<?php if (...): ?>` бесполезно — тег отрендерится всё равно.
12. **Пост-проверка должна быть отложенной.** Публикация уже расходует бюджет
    запросов, поэтому немедленный GET обычно упирается в защиту от флуда;
    догоняет её `check.py` отдельным запуском.

## Валидатор: что блокирует публикацию

**Контракт вёрстки** (снят с реальных статей сайта): только
`p, h2, h3, ul, li, strong, table, thead, tbody, tr, th, td, div, insert`; только
классы, которые стилизует тема; обязательны таблица сравнения, список, CTA-блок
и FAQ из 5–8 вопросов; лид — ровно два абзаца до первого `<h2>`, с числом в первом.

**AI SEO**: 5–9 контентных разделов, в каждом есть число; не меньше восьми
числовых фактов на статью; запрещены заголовки «Введение», «Заключение»,
«Итоги»; запрещены хеджи («возможно», «как правило»), рекламные штампы
(«лучший», «уникальный», «команда профессионалов») и клише.

**Ссылки**: 3–4 внутренние ссылки, каждая в своём `<h2>`; не в лиде, не в
таблице, не в FAQ и не в CTA; анкор 2–5 осмысленных слов.

Исследование, из которого выросли эти правила, — в
`docs/ai-seo-research-2026.md`, промпт, который их реализует, — в
`prompts/writer.md`.

## Диагностика

| Симптом | Причина и что делать |
| --- | --- |
| `403 forbidden — проверь PUBLISHER_TOKEN в .env` | Токен в `.env` не совпадает с залитым файлом — перезалейте: `python src/deploy.py publisher` |
| `ответ не JSON (HTTP 500)` | Ошибка PHP на сайте: смотрите тело ответа, проверьте версию PHP и что `publisher.php` лежит в корне |
| Запросы начинают отваливаться по таймауту | Защита хостинга от флуда — клиент сам держит паузу и бэкофф; подождите пару минут и держитесь одной статьи на запуск |
| FTP `LIST` не работает | Сервер его не поддерживает; клиент использует `MLSD`/`NLST` и одно соединение на запуск |
| Сразу после публикации адрес отдаёт 404 | Запись ушла в черновик — та самая ловушка ENUM, см. п. 1 |
| `Не найден python.exe` в задаче Планировщика | Задача запускается без вашего `PATH`; `ps-common.ps1` ищет Python в стандартных местах |
| Обложка осталась заглушкой | В реестре `image_provider = pillow_brand`; прикрепите свою через `set_cover.py` |

## Безопасность

- В репозитории нет секретов — только `.env.example`. Токен публикатора
  подставляется в файл при деплое.
- Endpoint без токена не делает ничего, на запись отвечает только на POST,
  отдаёт `X-Robots-Tag: noindex` и идемпотентен по `external_id`, поэтому
  повторный запуск не создаёт дубль.
- Публикация не разрушительна: сбой переобхода или пост-проверки оставляет
  статью опубликованной и догоняется отдельной командой. `delete` отправляет
  запись в корзину Diafan и удаляет только её собственные файлы картинок.
- Любая правка файла на сайте — после бэкапа
  (`python src/deploy.py backup <путь>`): предыдущая версия лежит в
  `data/backups/<дата>/` и откатывается одной командой.
- Данные исходной установки (домен, доступы, id хостинга, каталоги статей,
  артефакты прогонов, дампы базы) в этот репозиторий **не входят**.

## Оговорка

Конвейер публикует материалы на живой сайт. Сначала проверьте его на черновике
(`act=0` в payload) или на копии сайта и снимите бэкап таблиц `diafan_news`,
`diafan_rewrite`, `diafan_images` и папки `userfls/news/`. Автоматизация не
заменяет редакционную ответственность: инструмент следит за структурой и
запрещает выдуманные цифры, но за достоверность фактов, которые вы ему даёте,
отвечаете вы.
