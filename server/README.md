# server/ — что и куда деплоится

В этой папке — код, который живёт **на сайте**, а не на локальной машине.

| Файл | Куда кладётся на сайте | Зачем |
| --- | --- | --- |
| `publisher.php` | корень сайта, под случайным именем из `PUBLISHER_PATH` | единственная точка записи статей: INSERT новости + ЧПУ + загрузка картинки + сброс кэша |
| `show_anons.php` | `custom/my/themes/functions/show_anons.php` | переопределение шаблонного тега: анонс страницы «Блог» не выводится на страницах статей |

Деплой — по FTP, одним соединением за запуск (у хостинга жёсткий рейт-лимит):

```powershell
python src\deploy.py ls                    # что лежит в корне сайта
python src\deploy.py publisher             # залить publisher.php (подставит токен из .env)
python src\deploy.py put "server\show_anons.php" "custom/my/themes/functions/show_anons.php"
python src\deploy.py unpublish             # снять publisher.php с сайта (с бэкапом)
```

`deploy.py` при заливке заменяет в `publisher.php` строку
`$PUBLISHER_TOKEN = '__PUBLISHER_TOKEN__';` на значение из `.env`, поэтому
секрет никогда не лежит в репозитории.

## Действия publisher.php

| Вызов | Что делает |
| --- | --- |
| `GET ?action=inspect` | диагностика: схема таблиц, вариации картинок, образцы ЧПУ, версия CMS, права на запись |
| `POST ?action=publish` | публикация статьи (JSON в теле, `base64` обложки внутри) |
| `POST ?action=update` | правка уже опубликованной статьи по `id` |
| `POST ?action=set_image` | замена обложки у существующей статьи |
| `GET ?action=delete&id=N` | откат: запись в корзину Diafan + удаление файлов картинок |
| `GET ?action=clearcache` | сброс кэша Diafan (нужен после правок шаблонов) |

Авторизация — заголовок `X-Publisher-Token` (или `?token=`). Без верного токена
endpoint отвечает `403` и ничего не делает. Публикация идемпотентна по полю
`external_id`: повторный запуск с тем же `external_id` не создаёт вторую запись.

## Чего в репозитории нет

**Переопределения шаблона статьи** (`custom/my/modules/news/views/news.view.id.php`).
Это копия ядрового шаблона `modules/news/views/news.view.id.php` из Diafan.CMS —
кода вендора, а не нашего, поэтому в публичный репозиторий он не положен.
Изменение в нём ровно одно: блок `_images` перенесён **внутрь** `<div class="_text">`
и выводится перед текстом, чтобы сработало CSS-правило обтекания:

```php
echo '<div class="_text">';

// изображения новости — внутри _text, чтобы CSS обтекал их справа
if (! empty($result["img"]))
{
    echo '<div class="_images">';
    // ... вывод картинок как в ядровом шаблоне ...
    echo '</div>';
}

//вывод основного текста новости
echo $this->htmleditor($result['text']);

echo '</div>';
```

Как применить: скопировать ядровый шаблон в
`custom/my/modules/news/views/news.view.id.php` (Diafan сначала ищет шаблон в
`custom/`, поэтому обновление CMS такую правку не сотрёт) и перенести блок
`_images` внутрь `_text`. CSS сайта менять не нужно: правило для `_images`
внутри `_text` обычно уже есть — оно и включает обтекание. Подробности и грабли
(включая HTTP 500 при правке темы без бэкапа) — в `ARCHITECTURE.md`, §11.14
и §11.17.

**Правило перед любой правкой файла на сайте:** сначала бэкап
(`python src\deploy.py backup <путь>`), потом правка, потом проверка ответа 200.
Ошибка в файле темы роняет весь сайт в 500 — откат занимает секунды только
тогда, когда бэкап уже снят.
